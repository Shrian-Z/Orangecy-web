# Orangecy 产品完成度评估与主流化路线图

日期：2026-11-05  
状态：评估 + 计划，本轮不改代码。  
基准：以「公开可用、别人能长期用」为标准；同时给「个人日用」与「作品集 demo」两档参照。  
参考：`docs/plan/wordcard-content-and-scheduling-20261028.md`（内容层与调度研究）、`docs/research/study-apps-20261025.md`（主流 App 每日计划）。

---

## 0. 一页结论

**阶段：L1.5 / L4。可演示已经完成；个人日用完成一半；公开产品还没开始。**

| 目标 | 完成度 | 判断 |
| --- | ---: | --- |
| 作品集 / demo | 目标已达成（L1） | 200 词、三卡型、三键、FSRS、Pages 可打开 |
| 个人每天用 | 约 60–65%（L2 的一半） | 导入书可全量；预设书不可；没有备份/同步 |
| 公开给他人用 | 约 40%（保守 35–45%；L3–L4 未开始） | 内容、账户、合规、运维四个地基都缺 |

- **最强**：单词 × 真实歌词语境 + 全屏卡 + 音频序列 + 蓝白纪律。这是别人没有的，不要为了「像主流 App」推翻它。
- **最弱**：不是玩法，是地基——内容（预设词书只有 50 / 9 / 46 张可学卡）、复习（正式版没有「忘记」）、数据（只在本机）、上线（没有账户 / 同步 / 合规）。
- **一句话**：Orangecy 已经是一个「能演示、半能自用」的学习原型；要变成「别人能长期用」的产品，下一刀不是再加一个界面，而是把「词书 → 卡 → 复习 → 数据」补成闭环。

### 最紧急的一个事实

按当前代码路径：

- 四级 4,542 词，可学卡 **50 张**；
- 六级 3,991 词，可学卡 **9 张**；
- 高中 3,738 词，可学卡 **46 张**。

当这些卡都判过、且当天没有到期复习时，首页会显示「全部学完」，但书条进度只有 `50 / 4542`。  
这不是「内容少」，这是**产品在说谎**。它比缺一个统计页严重得多，应该排在 P0 第一位。

## 2. 已经做对了什么（不要推翻）

1. **差异化成立**：歌词片段 + 目标词高亮 + 真实时间戳 + 音频序列，是 Orangecy 唯一但足够强的不同。50 张 seed 卡全部有 `track / fragment / example`；导入高考 3,738 词在一次真实登录验收中出过 3,059 张歌卡 + 679 张纯词卡。
2. **专注成立**：一屏一词，没有歌单、搜索、推荐、弹窗；音乐只留四种痕迹。这个约束是资产，不是束缚。
3. **学习闭环成立**：N/M、每日新词/复习上限、完成态、「再学 10 个」、背完自动复习。这些已经对齐主流 App 的「计划可见、可调、有完成态」。
4. **工程纪律成立**：`check:palette` 42 状态、`smoke` 111 项、`trace:audio` 13 项、`check:cards` 484 项；当前 `typecheck` 通过。
5. **可演示成立**：200 词静态 demo + context / recall / cloze + 三键 + FSRS + 本地持久化。

**一个需要正视的不一致**：公开 demo 的卡链和三键，比正式版更完整。评审如果把 demo 当产品，会看到「演示比真实产品更好用」。Phase 0 要把 demo 的卡链/三键回灌正式版，或者明确 demo 只是切片。

**结论：主流化要加在地基上，不是换掉灵魂。**

## 5. 差距清单

### P0 — 不补就不能给别人用

1. **预设词书全量可学**，并修掉「全部学完」的假完成。
2. **正式版三键**（忘记 / 模糊 / 认识）+ 当天再现 + 撤销。
3. **学习数据可导出/恢复**；公开版需要账户 + 云同步。
4. **公开上线形态**：明确是「本地工具」还是「托管服务」；后者需要域名、账户、合规、运维。
5. **内容诚实**：每张卡有核心义 + 例句；无空卡；音频可用；来源/许可可追溯。

### P1 — 主流对齐

6. 词书目录、详情、搜索、进度。
7. 卡内容 v2：词性、多义、搭配、词族、助记、例句音频、考试义。
8. 统计、预测、连续天数、提醒。
9. 分级测试 / 跳过已会。
10. 生词本 / 难点词 / 暂停。
11. PWA / 离线 / 键盘 / 手势。
12. 每本书的计划与进度，而不是全局一刀切。

### P2 — 差异化 / 规模

13. 语境分发：选歌、选句、换语境，避免同一语境反复出现。
14. 7 天延迟回忆实验（北极星）。
15. A/B/C 内容分层 + 人工审核。
16. 轻社交 / 分享（谨慎，最后做）。

## 6. 产品决策点（先定，不然会返工）

1. **定位**：个人工具还是公开产品？建议先做「公开可用的单机版」（L3），验证 5–20 人后再平台化。
2. **音乐版权**：BYO account / licensed clips / text-only。建议公开版默认「文本例句 + 可选 BYO 音乐」；demo 不带音乐；不公开分发未授权歌词/音频。
3. **账户**：本地优先 + 可选云同步；不要一上来做复杂账户。
4. **词书数据模型**：全局单词记忆 vs 按书独立。建议全局记忆 + 按书进度/计划；避免同一个词在不同书里重复复习。但 UI 要说清「已学」是「这本书里你认识的词」，不是「从这本书新学的词」。
5. **卡片文字**：工具层允许必要文案，卡片层保持零废话。建议把 AGENTS 的例外从「设置页/完成态」扩展为「工具层 / 卡片层」两层。
6. **评分**：3 键可见 + Easy 隐藏（键盘 4 / 长按「认识」）。四键常驻会增加选择负担。
7. **内容来源**：ECDICT + 词书 + Tatoeba/LLM + 人工审核；A/B/C 分层；版权逐项确认。
8. **目标用户**：先考试党（CET4/6、考研、高考），因为词书和复习需求明确；歌词语境是差异化，不是唯一卖点。

## 7. 四个主战场的具体设计

### 7.1 如何复习

#### 评分语义

| 按钮 | FSRS | 用户语义 | 调度 | 备注 |
| --- | --- | --- | --- | --- |
| 忘记 | Again | 想不起来 / 认错 | 同会话 3–5 张后重现；FSRS 记 lapse | 必须有，这是失败信号 |
| 模糊 | Hard | 想起来但费力 | FSRS 计算，通常比 Good 短 | 保留 |
| 认识 | Good | 正常想起 | FSRS 计算 | 默认 |
| 太简单 | Easy | 秒认 | FSRS 计算，通常更长 | 隐藏，键盘 4 / 长按，避免四键常驻 |

**原则：一张卡只考一个义项；评分是「这次提取有多难」，不是「这个词重不重要」。**

#### 当天再现

- 点「忘记」后，不要立刻重试同一张卡；把它插到 **3–5 张之后**再出现。
- 理由：立即重复是 massed repetition，短时看起来会了，长期保留差；隔几张是 spacing。
- 当前 demo 是「同卡立即重试」，建议改；正式版还没有这个能力。
- 不改 FSRS 内核，只在 session 层做 requeue。

#### 学习步骤

- 新词：今天第一次见（语境卡）→ 同会话第二次提取（recall/cloze）→ 明天到期复习。
- 不要一上来做 Anki 的 1m/10m/1d 全套；Orangecy 的卡有音频、有语境，单卡时间长，步骤太多会拖垮会话。
- 如果以后要做，优先 `enable_short_term: true` + 1 个 learning step，不要开放给用户配。

#### 每日计划

- 保留现有：每日新词 5–100、每日复习上限 0/100/200/300/500。
- 新增：目标留存率（0.80 / 0.90 / 0.95）、最大间隔、顺序（先复习 / 先新词 / 混合）。
- 每本书可以有独立计划；默认继承全局，允许覆盖。
- 完成态：今日新学 / 复习 / 正确率 / 用时 / 还有多少到期；「再来一组」/「明天继续」。

#### 统计与预测

- 今日：新学、复习、到期、剩余。
- 未来 7/30 天到期预测（柱状图，只用蓝色 alpha）。
- 最近 30 天留存率、lapse 率、leech 率。
- 12 周热力图（蓝色 alpha 阶梯，不用绿/红）。
- 每张卡用时、每次会话用时。
- 难点词列表：连续失败 ≥ 4 次的词。

#### 特殊动作

- **撤销**：撤销上一次评分，恢复 FSRS 状态和队列位置。误触很常见，必须有。
- **暂停 / 埋藏**：今天不再出现（bury）vs 长期暂停（suspend）。
- **已掌握**：标记后不再进入新词队列；可撤销。
- **提前复习**：没有到期卡时，允许「自由复习」（不影响 SRS）或「提前复习」（影响 SRS，需提示）。
- **leech**：连续失败达到阈值，换卡型（cloze/listen）或暂停，不要无限重复。

#### 不要做

- 不要四键常驻。
- 不要无限重复同一张卡。
- 不要隐藏到期数量。
- 不要把「全部已学」标成「复习」。

### 7.2 单词卡内容

#### 数据模型 v2

| 字段 | 说明 | 正面 | 翻面 | 第二层 | 来源 |
| --- | --- | --- | --- | --- | --- |
| `w` | 单词 | ✓ |  |  | 词书 |
| `p` | 音标 | ✓ |  |  | 词书 / ECDICT |
| `pos` | 词性 |  | ✓ |  | 词书 / ECDICT |
| `coreSense` | 核心义，1 个 |  | ✓ |  | 人工 / ECDICT |
| `secondarySenses` | 次要义，≤2 |  |  | ✓ | 人工 |
| `example` | 例句 + 翻译 | 语境卡正面 | ✓ |  | 词书 / Tatoeba / LLM |
| `exampleAudio` | 例句音频 |  | ✓ |  | TTS / 真人 |
| `collocations` | 搭配 1–2 |  |  | ✓ | 语料 / 人工 |
| `wordFamily` | 词族 / 屈折 |  |  | ✓ | ECDICT `exchange` |
| `root` | 词根 / 助记 |  |  | ✓ | 审核过的来源 |
| `exam` | 真题句 + 来源 |  |  | ✓ | 词书 |
| `tags` | 考试 / CEFR / 频率 |  |  |  | ECDICT |
| `context` | 歌词 / 歌曲 / 时间 | 语境卡正面 |  |  | 用户歌单 |
| `tier` | A/B/C |  |  |  | 内容分级 |
| `license` | 来源 / 许可 |  |  |  | 元数据 |

**一张卡只考一个义项。** 多义项放第二层，不放在正面。

#### 卡链

| 卡型 | 正面 | 背面 | 适用 | 目的 |
| --- | --- | --- | --- | --- |
| context | 歌词/例句 + 目标词高亮 + 音频 | 词 + 音标 + 核心义 | 初见 | 语境与情绪连接 |
| recall | 词 + 音标 + 语境，义藏起 | 核心义 + 例句 | 学习 | 主动提取 |
| cloze | 语境挖空 + 中文提示 | 词 + 音频 | 巩固 | 形式与语境绑定 |
| listen | 只放音频 | 词 + 义 | 复习 | 听觉表征 |
| spell | 中文义 / 音频 | 拼写 | 产出 | 拼写与产出 |

选择规则（第一版，规则即可，不上模型）：

- 新词 → context；
- 第一次复习 → recall；
- 第二次 → cloze；
- 之后 → recall / listen / spell 轮换；
- leech → cloze 或 listen，给更多支撑；
- 用户可手动切换卡型，但默认自动。

#### 内容分级

| 层级 | 范围 | 内容 | 生产方式 | 目标 |
| --- | --- | --- | --- | --- |
| A | 3,000–5,000 核心/高频/考试词 | 核心义 + 1–2 例句 + 音频 + 搭配 + 考义 | 人工审核为主，ECDICT 打底 | 对标主流 |
| B | 10,000–20,000 次高频 | 核心义 + 例句 + TTS + 基础搭配 | 自动 + 抽检 | 可用、可扩展 |
| C | 长尾 | 词 + 音标 + 中文释义 + 词形 | ECDICT 直出 | 查得到、能认 |

首发不要做 77 万张卡。先把 A 层做扎实，B 层自动化，C 层诚实标注「基础卡」。

#### 音频

- 单词：美音 / 英音可选；TTS 兜底；A 层优先真人音频。
- 例句：先 TTS，A 层再换真人。
- 发音直出，不假淡入；片段仍是 0.2s 淡入淡出 + 0.5s 安静。
- 音频必须和词/例句对得上；TTS 也要标 provider。

#### 内容 QA

- 每张卡 `w / p / m` 非空。
- 例句必须包含目标词；翻译必须可读。
- 目标词高亮必须命中 surface。
- 无重复词；无空卡；无错位音标。
- 敏感/歧义/政治/医疗等内容人工抽检。
- 每个字段记录来源和许可证。

#### 不要做

- 不要图片记词：和两色设计冲突，而且容易教「图」不教「词」。
- 不要一次摊开 10 个义项。
- 不要伪造词根/词源；助记要标「助记」，不是「真理」。
- 不要用未授权例句/音频/歌词。

### 7.3 词书

#### 目录

第一批 10–15 本，覆盖考试党：

- 中考、高考、四级、六级、考研；
- 专四、专八、TOEFL、IELTS、GRE；
- 新概念 1–4（可选）；
- 商务 / 医学 / 计算机（后期）。

每本要有：`id / 名称 / 级别 / 词数 / 来源 / 许可 / 简介 / 是否完整 / 更新时间`。

#### 书详情页

- 书名、级别、词数、来源。
- 进度：未学 / 学习中 / 已掌握。
- 预计完成天数（按当前每日新词）。
- 前 10 个词预览。
- 「开始 / 继续 / 换计划」。
- 不展示封面上图（避免第三类图片例外）；用排版和数字。

#### 进度定义

- **未学**：没有 SRS 记录。
- **学习中**：有记录，间隔 < 21 天。
- **已掌握**：间隔 ≥ 21 天，或 FSRS 稳定度达到阈值。
- 书条显示「已学 / 总量」时，要明确「已学」= 这本书里你认识的词，不是「从这本书新学的词」。

#### 全局记忆 vs 按书独立

- 建议：**全局单词记忆 + 按书计划/进度**。
- 理由：同一个词在四级和六级都出现，不应该复习两遍；用户要的是「认识这个词」，不是「完成两本书的重复劳动」。
- 代价：书进度会受其他书影响；UI 要解释清楚。
- 如果以后用户强烈要求「按书独立」，再加开关，不要现在做。

#### 导入 / 导出 / 去重 / 合并

- 导入：JSON / CSV / TSV / TXT；预览书名、词数、前四个词；支持列映射。
- 去重：同一本书重复导入时提示「已存在」；可选择覆盖 / 新建副本 / 合并。
- 合并：两本自定义书合并，按词去重。
- 导出：词书 + SRS 状态 + 学习日志，JSON；可选 CSV。
- 删除：二次确认；可撤销（软删除 7 天）。

#### 分级测试

- 20–30 道有对错的小题，覆盖不同词频/词族。
- 根据正确率、反应时、提示次数估计起点。
- 不要问「你认识哪些词」——自评不可靠。
- 结果：建议从第 N 个词开始；可 bulk mark known。

#### 不要做

- 不要上 100 本书却没有完整卡。
- 不要虚标词数。
- 不要按书重复 SRS。
- 不要把「导入」藏在只有文件图标的地方；至少在空态/书列表给一个可发现的入口。

### 7.4 如何背单词

#### 首次进入（onboarding）

最多 3 步，全部用图标 + 数字，不写长说明：

1. **目标**：考试 / 提升 / 兴趣（3 个选项）。
2. **词书**：按目标推荐 2–3 本；可跳过，进书列表。
3. **每日计划**：5 / 10 / 20 / 30（默认 10）；可跳过，用默认。

可选：分级测试（20–30 题），放在「开始」之前，不强制。

#### 每日循环

1. 首页：今日新词 / 复习 / 连续天数 / 书进度。
2. 主按钮「开始今日学习」；次按钮「只复习」。
3. 会话：卡链 → 评分 → 自动下一张；可暂停、撤销。
4. 结束：新学 / 复习 / 正确率 / 用时 / 到期；「再来一组」/「明天继续」。
5. 次日：到期队列自动出现；连续天数 +1；提醒。

#### 会话编排

- 先复习后新词（默认），可切换。
- 新词队列走完自动接到期复习（已有）。
- 每 10–15 张给一次「休息」提示（可选，不强制）。
- 单次会话建议 10–20 分钟；超过 30 分钟提示休息。
- 不做一个无限流；必须有停止点。

#### 习惯

- 每日提醒：Web Push / 邮件；时间可调；默认关闭，首次完成后再问。
- 连续天数：完成「今日最低目标」即可 +1；允许 1 次冻结/月，避免断签焦虑。
- 周报：本周新学、复习、留存、用时、难点词。
- 不做排行榜、不做小组、不做强制打卡。

#### 难点词

- 自动收集：lapse ≥ 4 或连续 3 次「忘记」。
- 手动收藏：卡上长按 / 详情页星标。
- 难点词可以单独复习，也可以换卡型。
- 提供「我已经会了」出口，避免死循环。

#### 桌面 / 手机交互

- 桌面：Space 翻面，1/2/3/4 评分，R 重播，P 发音，U 撤销，Esc 返回。
- 手机：上滑翻面；左滑「忘记」、右滑「认识」（需二次确认/可撤销，防误触）；点歌词重播；点单词发音。
- 减少动态效果时，切卡动画归零；音频时间轴照走。
- 触控目标 ≥ 44px；安全区适配；短屏卡内滚动。

#### 不要做

- 不要无限流 / 短视频式分发。
- 不要社交压力 / 排行榜。
- 不要过度游戏化（金币、徽章、抽卡）。
- 不要为了停留时长而加内容。

## 8. 保留差异：哪些主流东西不要抄

1. **图片记词**：和两色设计冲突；容易教「图」不教「词」。
2. **无限流 / 短视频**：学习需要停止点；优化时长会奖励简单词和娱乐内容。
3. **社交 / 排行榜**：压力、审核、冷启动；不是学习内核。
4. **过度游戏化**：连续天数可以，金币/徽章/抽卡不要。
5. **多义项一次全考**：认知过载；一张卡一个义项。
6. **词典式长文**：卡不是词典；分层展开。
7. **未授权歌词 / 音频**：公开上线最大风险。
8. **第四 tab**：统计、词书详情、设置都 push，不占底栏。

**Orangecy 的不同不是「更少的功能」，而是「更少的干扰 + 更真实的语境」。**

## 9. 指标与验收

### 北极星

> 7 天后，到期词在**新语境**（另一首歌 / 另一条例句）中的无提示回忆率。

### 辅助指标

- 激活：首次会话完成、首日学 10 词、首次复习完成。
- 留存：D1 / D7 / D30、连续天数、周活。
- 学习：留存率、lapse 率、leech 率、新词毕业率、单卡用时。
- 内容：卡覆盖率、例句覆盖率、音频覆盖率、QA 通过率。
- 约束：单次会话时长、第 N 张流失、自评难度。

### 不要做北极星

- DAU、停留时长、连续天数。它们可以做约束/辅助，不能做目标。

### L3 的 Definition of Done

- 一个陌生人打开 URL，10 秒内知道这是什么。
- 选一本完整词书，学 10 个，明天回来能看到到期复习。
- 数据不丢：刷新、换设备（或导出/恢复）后还在。
- 每张卡有核心义 + 例句；没有空卡/错卡；音频可播。
- 手机 Safari / Chrome 可用；console 0 error。
- 有隐私政策、服务条款、数据删除入口；音乐版权策略清楚。
- 有反馈入口；5–10 个真实用户用过 7 天。

## 11. 风险与开放问题

1. **音乐版权**：歌词/音频公开分发的权利是否清楚？BYO account 是否足够？平台 API 是否稳定？
2. **内容质量**：3,000 张 A 层卡的人工审核需要多少时间？谁审？如何抽检？
3. **单人产能**：工程 + 内容 + 运营三件事，是否要砍到「单书 + 单端」？
4. **留存**：没有社交/游戏化，靠什么让用户第 7 天回来？语境 + 计划 + 提醒是否足够？
5. **TTS 质量**：浏览器 TTS 在 iOS/Android 差异大；是否要为 A 层预渲染？
6. **同步复杂度**：离线优先 + 多端冲突，是否值得在 L3 前做？
7. **范围蔓延**：歌单世界、平台连接、导入配歌都很诱人，但它们不是「别人能长期用」的瓶颈。
8. **HAA 与产品**：今天是 HAA 截止日；这份计划是截止后的产品路线，不与申请材料抢范围。
