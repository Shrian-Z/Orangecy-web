## 二、AI 该做的（你只需要把任务丢给它）

### 1. 修公开页的问题

把手机实测的 3 个问题原样贴给 AI：

> 这是我的公开 demo：https://shrian-z.github.io/Orangecy-web/
> 这是我手机上的 3 个问题：1）… 2）… 3）…
> 请直接在这个仓库里改代码、重新构建并部署到 gh-pages；不要让我执行命令。
> 改完告诉我：改了哪些文件、公开链接、我怎么在手机上复测。

### 2. 审 200 张卡

> 请检查 `src/data/demo-200.json` 的 200 张卡：
> 1）例句是否包含目标词；2）中文翻译是否准确自然；3）释义是否适合四级；
> 4）有没有太敏感/太偏的词。
> 先只给我“最差的 20 个 + 替换建议”，不要改代码。

### 3. 准备本地真实音乐录屏

> 请把本地项目切回完整模式，启动服务，确认 `http://127.0.0.1:8787`
> 能打开 seed-50，并且卡片能播放真实歌词片段和发音。
> 不要改公开 GitHub Pages 的 demo。我只需要录 30–45 秒真实音乐卡。
> 如果需要我扫码登录，一步一步告诉我。

### 4. 写 HAA 申请答案

> 这是我的 3 个事实：…（贴你备忘录里的 3 条）
> 请基于 `docs/haa/README.md` 和公开 demo，写 HAA 申请答案。
> 要求：诚实；不编造用户/留存数据；明确说 200 词、TTS、公开 demo 没有音乐版权；
> 语气像 builder，不像学生作文。先给 3 个版本让我选。

### 5. 写用户测试邀请

> 帮我写 5 条发给同学/朋友的测试邀请，和 3 个试用后的问题。
> 不要营销腔；目标是拿到真实反馈，不是让他们夸我。

### 6. 视频字幕 / 剪辑

> 这是我 90 秒视频的录音转写：…
> 请帮我压到 90 秒以内，保留“词在歌词里 / 先回忆再翻 / 忘记会回来 / 200 词不是全量”四个点。
> 输出一版中文字幕和英文旁白。

## 三、你不需要做的事

- 不要学编程、不要学 Terminal、不要学 Git。
- 不要扩到 3,000–5,000 词；这周做不完，质量也保证不了。
- 不要等“公开音乐播放”做完；版权和后端不是一周能解决的。
- 不要做 logo、落地页、动画、排行榜。
- 不要编造用户数、留存率、融资、合作。
- 不要把 GitHub token、密码、HAA 账号交给任何 AI。
- 不要在公开 repo 上传完整歌曲/歌词；本地录屏只用于申请视频。

## 四、你必须能讲清楚的 5 个产品决定

HAA 会问“你做了什么”，不一定会问代码。你要能用自己的话说清楚：

1. **为什么是一屏一词，不是词书列表/仪表盘？**  
   背单词只有一件事：此刻这个词。信息越少，越容易开始。
2. **为什么用歌词语境，而不是通用例句？**  
   真实歌曲有情绪和声音钩子；例句只给用法，歌词给“记忆场景”。
3. **为什么三种卡：context / recall / cloze？**  
   同一个词，先理解、再回忆、再补全；不是一张卡刷到底。
4. **为什么三个判断：忘记 / 模糊 / 认识？**  
   人自评会失准；没有“忘记”，就没有失败信号，间隔会被拉长。
5. **为什么公开 demo 只有 200 词、没有音乐？**  
   一周内只能做诚实的最小闭环；音乐版权和后端没解决，不拿假数据/盗版音频充数。

如果这 5 个问题答不上来，让 AI 陪你做一次 10 分钟模拟面试。

## 六、怎么介绍“我用 AI 做的”

不要说“我不会编程，所以是 AI 做的”。  
说：

> “I don't write code by hand; I use AI as my build system. I make the product decisions, test on device, talk to users, and ship. The live demo, the 200-word deck, the card chain and the Pages deploy are all shipped; here is the link.”

这是诚实、且符合 HAA 的 proof-of-work 文化。  
AI 是工具，不是作者；产品判断、取舍、测试、叙事是你的。
